## Deterministic defect

The original `MarketDataService::fetch_history()` already applies `history_integrity::decode()` to provider history before the MCP `get_history` response, courtesy of Fincept draft #62. The **separate original `MarketDataService::refresh()` DataHub `batch_all` history path still used `QJsonValue::toDouble()` on each field**, which silently turns missing/null/non-numeric OHLCV into zero, and it published empty histories as successful series. This is not safe for general Fincept chart consumers or eventual KAIROS research tools. Separately, the original Python `yfinance_data.py::get_batch_all()` converted an empty/errored provider result into `"points": []` **without an error marker**, laundering a provider outage as apparent success.

## Exact minimal fix

- The original C++ DataHub `batch_all` history conversion now calls **the same** `history_integrity::decode(QJsonDocument(pts))` as single-history/MCP. It fails closed if any bar is missing, nonfinite, duplicated, out of sequence, implausible, malformed or if the series is empty/oversized. It calls `hub.publish_error(topic, "invalid or unavailable batch history")` and does **not** call `publish_history_to_hub` or increment `hists_ok`. Fully valid history is forwarded without changing its bar values. This also removes the former `toDouble()` zero-imputation fallback in this specific batch-history branch.
- The original Python `get_batch_all()` returns explicit generic `"error": "HISTORY_UNAVAILABLE"` plus an empty `points` list when the provider history is empty, malformed, a non-list error envelope, or raises an exception. Raw provider exception strings can contain sensitive URLs, cookies or account details and are **not copied** into the shared response. The preexisting `get_historical_period` public API and valid batch history schema are unchanged. Other quote, sparkline, provider, broker or MCP tool behaviors are not modified.
